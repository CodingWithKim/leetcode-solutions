## 📜 Commit Message Guidelines

To maintain absolute cleanliness and repository discipline, I strictly follow the **Conventional Commits** specification. Here is my quick reference table:

| Type | Scope / Example | Description |
| :--- | :--- | :--- |
| **`feat`** | `feat(0001): add optimal hash map solution` | Solved a brand new problem. |
| **`fix`** | `fix(0020): handle edge case for empty string` | Fixed a bug, failing test, or improved suboptimal performance. |
| **`docs`** | `docs(0015): add time complexity analysis` | Updated READMEs, code comments, or explanations. |
| **`refactor`** | `refactor(0094): convert recursive to iterative` | Rewrote code to be cleaner/more efficient without changing the problem. |
| **`chore`** | `chore: update auto-generation script` | Changes to project tooling, CI/CD pipelines, or automation scripts. |

> **Commit Example:**  
> `git commit -m "feat(0001): add optimal hash map solution for two sum"`<br>
> `git commit -m "fix(0020): handle edge case for empty string in valid parentheses"`<br>
> `git commit -m "docs(0015): add time complexity analysis in comments"`<br>
> `git commit -m "refactor(0094): change binary tree traversal from recursive to iterative"`<br>
> `git commit -m "chore: update github action for readme auto-generation"`
